## 1. 目的とスコープ

### 1.1 アプリの目的
夫婦・パートナー関係に悩むユーザーが、日々の悩みや心配事を投げかけると、心理学・男女コミュニケーションの知見に基づき **優しく共感し、実践可能なワンポイントアドバイスを返す** チャットアプリを提供する。

### 1.2 v1.0 スコープ
| 区分 | 内容 |
| --- | --- |
| ✅ 含む | 単一画面のチャットUI／Gemini による応答生成／ストリーミング表示／セッション内の会話履歴保持／システムプロンプトによる人格・知識の定義 |
| ❌ 含まない（将来） | ユーザー認証・アカウント／会話ログの永続化／管理画面／多言語対応／課金 |

### 1.3 用語
- **心の通信線**: 事実・正論よりも先に、相手の感情を肯定して繋ぐ共感の回路。本アプリの応答方針の中核概念。
- **ワンポイントアドバイス**: 十分に共感した後に添える、今日から実践できる小さな行動提案。

## 3. アーキテクチャ

### 3.1 構成概要
Streamlit の単一プロセスがフロント（ブラウザUI）とバック（Gemini呼び出し）を兼ねる。永続ストアは持たず、会話状態はブラウザセッションに紐づく `st.session_state` のみに保持する。

```
[ブラウザ / ユーザー]
        │  ①悩みを入力 (st.chat_input)
        ▼
[Streamlit アプリ (app.py)]
        │  ②session_state に user メッセージ追加
        │  ③履歴を Gemini 形式へ整形
        ▼
[Google Gemini API (gemini-2.5-flash)]
        │  ④system_instruction + 履歴 で応答生成 (stream=True)
        ▼
[Streamlit アプリ]
        │  ⑤チャンクを逐次描画（ストリーミング）
        │  ⑥完了応答を session_state に保存
        ▼
[ブラウザ / ユーザー]  ⑦タイムラインに表示
```

### 3.2 処理フロー（詳細）
1. 起動時に `st.secrets` から `GEMINI_API_KEY` を取得。失敗時はエラー表示し、以降のAI応答を無効化。
2. `st.session_state.messages` が未初期化なら空リストで初期化。
3. 既存の全メッセージを `st.chat_message` でタイムライン描画。
4. `st.chat_input` でユーザー入力を受け取る。
5. 入力を `messages` に `{"role": "user", ...}` として追加し、即座に描画。
6. APIキーがある場合のみ：
   - `genai.configure(api_key)` → `GenerativeModel(model_name, system_instruction)` を初期化。
   - `messages`（最新のユーザー入力を除く）を Gemini の `history` 形式（`role`: `user`/`model`, `parts`: [text]）へ変換。
   - `start_chat(history)` → `send_message(prompt, stream=True)` で応答をストリーミング取得。
   - チャンクを結合しつつ末尾カーソル `▌` 付きで逐次描画、完了後にカーソルなしで確定描画。
   - 応答を `{"role": "assistant", ...}` として `messages` に保存。
7. 例外発生時はフォールバックメッセージを表示（§6 参照）。

### 3.3 状態モデル
`st.session_state.messages: list[dict]`

| キー | 型 | 値 |
| --- | --- | --- |
| `role` | str | `"user"` または `"assistant"` |
| `content` | str | メッセージ本文（Markdown） |

Gemini API 送信時のみ `role` を `user`/`model` に写像する（`assistant` → `model`）。

## 5. AI 振る舞い仕様（System Instruction）

`GenerativeModel` 初期化時の `system_instruction` に以下を組み込む。**この文言仕様が応答品質の正規定義**であり、変更はレビュー対象とする。

### 5.1 ペルソナ
心理学と男女コミュニケーションの専門家であり、「**Welfamily**」というブランド名で優しく寄り添う心の伴走者。名乗る際は必ず「Welfamily」とする。

### 5.2 ベース知識（ナレッジ）
- 女性脳は共感欲求が高く、「わかる、わかる」と共感されることで過剰なストレス信号が沈静化する。
- 会話の目的の違い：女性は共感、男性は問題解決。
- 女性脳は体験記憶に感情の見出しを付けて収納するため、一つの出来事が過去の関連記憶を一気に引き出すことがある。
- 「事実の通信線」より前に、相手の心を肯定する「**心の通信線**」を繋ぐことが重要。正論を突きつけない。
- 夫一筋・家庭一筋の妻ほど、期待の裏返しとして「怒り」を抱えやすい。
- 不満はコップに1滴ずつ水が溜まるように蓄積する（**セキュリティ問題**）。日々の気遣いと感謝が重要。
- 会話がない状態は不満のサイン。気遣いや小さな褒め言葉が関係改善に繋がる。
- 「こうしてほしい（接近）」と「回避」の悪循環に陥った場合は、自己内面の理解や第三者（カウンセリング）の視点が有効。

> 参照ナレッジソース（システムプロンプト整備時の背景資料）:
> - 記録フォルダ1: https://drive.google.com/drive/folders/162W_r3XoGzLlpe_TPcNYYPg-S3bm1MmC
> - 記録フォルダ2: https://drive.google.com/drive/folders/1V9WsB5-MGnE-Vrr0TUjfzWFylyGHgBY9

### 5.3 応答ルール
1. ユーザーの感情（不安・怒り・悲しみ等）を**絶対に否定しない**。まず深く受け止めて共感する。
2. 問題解決を急がず、「心の通信線」を繋ぐことを最優先にする。
3. 専門用語を多用せず、温かく優しいトーンで語りかける。
4. 長すぎない構成にし、今日から実践できる「ワンポイントアドバイス」を添える。
5. 名乗る際は「Welfamily」とする。

> 備考: 現行 `app.py` は 5.2 の一部（体験記憶・接近回避等）を簡略化している。v1.0 の正は **本仕様書 §5.2 の全項目**とし、`app.py` のシステムプロンプトを本仕様に揃えることを推奨する（`app260517.py` が全項目版に相当）。

## 6. エラーハンドリング仕様

| 事象 | 挙動 |
| --- | --- |
| APIキー未設定（`KeyError`） | `st.error` で「システムエラー: APIキーが設定されていません。管理者に連絡してください。」を表示し、以降のAI応答処理をスキップ。 |
| 応答生成中の例外（Rate Limit・通信断等） | 生のスタックトレースは表示しない。**キャラクターのトーンに合わせたフォールバック**を表示する。 |

**推奨フォールバック文言**（[非機能要求書](../non_functional_requirements.md) §5）:
> 申し訳ありません、現在少しお返事の準備に時間がかかっています。少し時間をおいてから、もう一度お話しを聞かせてくださいね。

> 現行 `app.py` は `st.error(f"エラーが発生しました: {e}")` と生エラーを出しているため、v1.0 では上記フォールバックへ変更すること（§9 差分参照）。

## 7. セキュリティ・プライバシー仕様

- **APIキー**: ハードコード禁止・画面入力禁止。`st.secrets["GEMINI_API_KEY"]`（本番）／`.streamlit/secrets.toml`（ローカル）でのみ参照。
- **シークレット流出防止**: `.streamlit/secrets.toml`, `.env`, `__pycache__/`, 仮想環境を [`.gitignore`](../.gitignore) に登録済み。
- **通信**: HTTPS 環境でホストする。
- **対話データ**: サーバーに永続保存しない。`st.session_state` の一時メモリのみで保持し、ブラウザセッション終了で消滅。
- **将来のログ蓄積時**: PII を含まないアノニマイズ形式とする。

## 10. 受け入れ基準（Acceptance Criteria）

| ID | 基準 | 検証方法 |
| --- | --- | --- |
| AC-1 | `streamlit run app.py` がエラーなく起動する | ローカル起動 |
| AC-2 | 「最近、パートナーが冷たくて会話がなく、不安です」に対し、否定せず共感し、ワンポイントアドバイスを含む応答が返る | 手動テスト（下記シナリオ） |
| AC-3 | 応答がストリーミングで逐次表示される | 目視 |
| AC-4 | 複数ターン会話で文脈（履歴）が維持される | 連続入力 |
| AC-5 | APIキー未設定時にシステムエラーが表示され、アプリが落ちない | secrets を空にして起動 |
| AC-6 | API例外時にフォールバック文言が表示される（生エラー非表示） | キー無効化／通信遮断 |
| AC-7 | `secrets.toml` が Git 追跡外である | `git status` / `git check-ignore` |
| AC-8 | モバイル幅で表示崩れがない | ブラウザ幅 375px で目視 |

### 10.1 代表テストシナリオ
- **入力**: 「最近、パートナーが冷たくて会話がなく、不安です」
- **期待**: ①不安を否定せず受容・共感する導入 → ②心の通信線に触れる → ③今日からできる小さな一歩（例: 感謝や気遣いの一言）を提案 → ④温かく短い締め。専門用語の多用がない。
